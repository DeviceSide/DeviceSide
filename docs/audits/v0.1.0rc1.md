## Pass 1

# a518efe..a909e9d audit: 2026-11-16 (v0.1.0rc1, pre-run)

This record replaces the earlier v0.1.0rc1 record (passes to `a43bc1e`), which no RC was cut from. Pass 1 covers the
whole range from v0.0.1 (`a518efe`) to `main` at audit time (`a909e9d`). Six reviewers each read a slice of the shipped
tree in full: core and actions; Hue, Shelly, Matter and Control4; ZHA with the shared ZCL modules; Zigbee2MQTT; release
scripts and CI; tests. The focus was `b025363..a909e9d`, the work since the last audited head. The never-merged fix
branch `claude/festive-goldberg-fcaowp` (93 commits off `5aae1fe5`) was checked commit by commit against `a909e9d`:
all 19 of its still-relevant fixes are still needed, and they appear below as findings. Every Critical and High was
re-read against the code before it went in.

**Verdict.** The architecture holds: every adapter plans before any send, failures stay per target, the tests use fake
clocks. It has **0 Critical, 10 High, 12 Medium, about 40 Low**. Half the Highs are one theme: log lines that still
carry device addresses, tokens or no consequence (H1-H6), which `docs/logging.md` forbids and the unported fix branch
had already fixed. The others are a Shelly RGBW color read wrong (H7), a Z2M stop that a quick tap loses on a Hue bulb
(H8), and two release-gate holes in `scripts/check_release.py` (H9, H10).

Ground truth: 2469 tests pass offline in 59 s. The slowest is
`tests/integrations/zigbee2mqtt/test_turn_on_for.py::test_group_with_fields_calls_turn_on_then_publishes` at 5.0 s,
a real wait (below).
